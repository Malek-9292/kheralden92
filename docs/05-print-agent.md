# تكامل الطباعة وPrint Agent

## الحالة الحالية
تم إنشاء سجل الطابعات وطابور مهام الطباعة على الخادم، وتُنشأ مهمة تذكرة مطبخ تلقائيًا داخل نفس معاملة إنشاء الطلب، وتُنشأ فاتورة العميل عند تسجيل التحصيل النقدي إذا كانت طابعة الكاشير مسجلة. تم توفير واجهات تسجيل الطابعة وإصدار رمز جهاز سري، وسحب المهام وتأكيد نجاحها أو فشلها، وإعادة طباعة تذكرة المطبخ من لوحة الطلبات، وإعادة جدولة المهام الفاشلة من شاشة الطابعات. تتضمن حمولة المهمة حقل `lines` عربي جاهز للطباعة بالإضافة إلى الحقول التفصيلية.

هذا لا يعني أن الطابعة الفعلية تعمل الآن؛ تطبيق Android Print Agent الذي يفتح USB Host ويطبع ESC/POS على Epson TM-T20 ما زال مطلوبًا، ويجب اختباره على الجهاز والطابعة الفعليين قبل اعتماد الإطلاق (DEC-012). لا يمكن إغلاق Phase 6 بالكامل دون اختبار عتاد.

## تسجيل الطابعة
من لوحة الإدارة افتح /admin/printers ثم سجل طابعة:
- الاستخدام: تذاكر المطبخ.
- الاتصال: USB.
- الاسم المقترح: Epson TM-T20.
- الكود المقترح: KITCHEN-01.

سيظهر رمز الجهاز مرة واحدة. انسخه إلى إعدادات Print Agent ولا تضعه في Git أو ملفات عامة. عند تدوير الرمز يجب تحديثه داخل التطبيق؛ الرمز السابق يتوقف فورًا.

## واجهات Print Agent
كل الطلبات تستخدم HTTPS في الإنتاج، وHeaders:
- X-Printer-Code
- X-Printer-Token
- Accept: application/json

### سحب مهمة
POST /api/print-agent/jobs/claim

الاستجابة إما job: null أو مهمة تحتوي:
- id
- job_type مثل kitchen_ticket
- attempt
- payload ويتضمن بيانات الطلب والأصناف والعنوان والمبالغ بالدينار الكويتي.

### تأكيد الطباعة
POST /api/print-agent/jobs/{jobId}/complete

لا يُسجل نجاح المهمة إلا بعد أن يؤكد تطبيق الجهاز اكتمال إرسال البيانات للطابعة.

الاستدعاء **idempotent**: إعادة `complete` على مهمة مكتملة مسبقًا تُرجع 200 مع `idempotent: true` دون تغيير الحالة. هذا يغطي حالة نجاح USB مع فقدان رد HTTP.

### الإبلاغ عن فشل
POST /api/print-agent/jobs/{jobId}/fail

Body مثال:
    {"error":"USB device disconnected"}

تُعاد جدولة المهمة بتأخير متزايد، ثم تتوقف بعد خمس محاولات. المهام التي ظلت في حالة processing لأكثر من ثلاث دقائق يمكن استعادتها من الطابور.

`fail` على مهمة مكتملة أو مُعاد جدولتها مسبقًا يُتجاهل بأمان (`idempotent: true`) حتى لا يفسد complete ناجحًا بلاغ فشل متأخر.

## تطبيق Android
يوجد التطبيق داخل `android-print-agent/` مع: شاشة إعداد، حفظ رمز الجهاز في Android Keystore، خدمة foreground، تحويل العربية إلى صورة ESC/POS (مع تفضيل `payload.lines`)، كتابة USB bulk، فلتر `USB_DEVICE_ATTACHED`، وتتبع محلي لمعرّفات المهام المطبوعة لإعادة `complete` دون إعادة الطباعة. يوجد workflow لبناء APK تجريبي. **لا تُعتمد قبل اختبار Epson TM-T20 الفعلي (DEC-012)** — راجع دليل المالك في متجر المشروع `hardware-print-qa.md`.

## متطلبات تطبيق Android
1. يعمل كخدمة/تطبيق Android مستقل، وليس داخل صفحة PWA.
2. يطلب USB permission من النظام عند توصيل الطابعة.
3. يتأكد من أن الجهاز USB Printer متصل قبل المطالبة بالمهام.
4. يحول payload إلى ESC/POS مع دعم العربية RTL واتجاه النص وعرض 80mm.
5. يطبع تذكرة المطبخ أو فاتورة العميل حسب job_type، ثم يرسل complete بعد نجاح الكتابة إلى USB.
6. يرسل fail عند الانقطاع أو الخطأ، مع رسالة واضحة.
7. يحتفظ برمز الجهاز محليًا في Android Keystore، ولا يكتبه في Logcat.
8. يعمل polling بفاصل قصير مع backoff عند عدم الاتصال، ويتوقف عن سحب المهام إذا كانت الطابعة غير متصلة.
9. اختبار الطباعة يجب أن يغطي العربية، أسماء الأصناف، الكميات، ملاحظات العميل، وعنوان التوصيل.

## ملاحظات السلامة
- لا تعرض رمز الطابعة في تقارير الأخطاء.
- لا تسمح للطابعة بسحب مهام فرع آخر.
- لا تؤكد المهمة قبل اكتمال الطباعة.
- لا تعتبر اختبار API بديلًا عن اختبار USB الفعلي على Epson TM-T20.
