## قواعد التنفيذ
- لا يبدأ تنفيذ وحدة أعمال قبل اعتماد تصميمها وعقودها.
- كل مرحلة تنفذ في فرع Git مستقل أو Pull Request قابل للمراجعة.
- يمنع دمج أي تغيير إلى main دون مراجعة واختبارات ناجحة.
- لا يُربط النظام بقاعدة الإنتاج أو بيانات المطعم الحقيقية أثناء التطوير.
- لا تنشر أسرارًا أو بيانات اعتماد في المستودع.
- لا يتم إعلان اكتمال وظيفة قبل وجود اختبار يثبتها.
- الوحدات المؤجلة (المخزون، الموردون، المشتريات، المصروفات) لا تدخل أي مرحلة من هذه الخطة.

## معايير قبول عامة
1. جميع اختبارات الوحدة والتكامل والميزات الأساسية ناجحة.
2. تطبيق صلاحيات الفرع والدور على الخادم.
3. الحسابات المالية مطابقة لقواعد KWD الثلاثية.
4. منع التكرار عند إعادة إرسال الطلبات أو مهام الطباعة.
5. سجل تدقيق لكل عملية حساسة.
6. اختبار فعلي للطباعة على طابعات المطعم والأجهزة المستهدفة.
7. اختبار استعادة نسخة احتياطية خارج الخادم.
8. موافقة المالك على نتائج UAT قبل الإنتاج.
