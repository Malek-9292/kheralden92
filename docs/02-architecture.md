# التصميم المعماري — نظام فتوش الخالدية

| الحقل | القيمة |
|---|---|
| المعرّف | FRS-ARCH-001 |
| الإصدار | 0.1 |
| الحالة | مسودة تصميم مستخلصة من SRS والقرارات المعتمدة |
| النمط | Modular Monolith |

## 1. المبادئ
1. تطبيق واحد ونشر واحد، مقسم إلى وحدات مستقلة بحدود واضحة؛ لا Microservices في المرحلة الحالية.
2. لا تتبادل الوحدات الوصول المباشر إلى جداول أو تفاصيل تنفيذ وحدات أخرى؛ يكون التكامل عبر عقود وخدمات تطبيقية وأحداث نطاق.
3. كل وحدة تملك نماذجها وقواعدها وترحيلاتها وسياساتها.
4. Module Manager مسؤول عن تفعيل الوحدات والتحقق من اعتمادياتها. التعطيل لا يحذف الشيفرة أو البيانات.
5. فصل بيئات التطوير والاختبار والإنتاج وقواعد بياناتها وبيانات اعتمادها.
6. الخادم هو المرجع النهائي للأسعار والخصومات والرسوم والصلاحيات وحالة الطلب.
7. تخزين المبالغ في DECIMAL(12,3) بالدينار الكويتي، لا FLOAT أو DOUBLE.
8. توقيت الأعمال Asia/Kuwait، مع تخزين التوقيتات بصورة موحدة وعرضها بتوقيت الفرع.

## 2. الطبقات
- Presentation: واجهة العميل PWA، لوحة الإدارة، شاشة الكاشير، Livewire وواجهات API.
- Application: حالات الاستخدام، تنسيق العمليات، التحقق من الصلاحيات، المعاملات.
- Domain: الكيانات وقواعد العمل والأحداث والعقود.
- Infrastructure: MySQL، التخزين، الطوابير، الإشعارات، Print Agent، النسخ الاحتياطي والمراقبة.

## 3. الوحدات وحدود المسؤولية
| الوحدة | المسؤولية |
|---|---|
| Identity | حسابات الموظفين والعملاء، المصادقة والجلسات |
| AccessControl | الأدوار والصلاحيات وسجل محاولات الوصول |
| Branches | الفروع وإعداداتها وربط الموظفين بالفروع |
| Catalog | الأقسام والأقسام الفرعية والأصناف والصور والإضافات والأسعار |
| Storefront | واجهة العميل وPWA والبحث ومشاركة الروابط |
| Cart | السلة والتحقق من تغير الأسعار والرسوم |
| Orders | إنشاء الطلب ودورة حياته والإلغاء والرفض وإعادة الطلب |
| Delivery | المناطق والعناوين والرسوم والحدود الدنيا وساعات الاستقبال |
| Payments | تسجيل وسيلة الدفع والتحصيل النقدي فقط وفق حدود SRS |
| Cashier | شاشة الكاشير والورديات واستلام الطلبات |
| Kitchen | تذاكر المطبخ وملاحظات التحضير الداخلية |
| Printing | تعريف الطابعات ومهام الطباعة وإعادة المحاولة وسجل الطباعة |
| Promotions | الخصومات والكوبونات وشروط الاستخدام |
| Notifications | التنبيهات الداخلية وسجل الإشعارات |
| Reporting | التقارير اليدوية والتصفية والتصدير |
| Content | البانرات والنصوص والهوية والألوان والأسئلة الشائعة |
| CustomerService | رسائل الاستفسارات العامة والتقييمات وفق قرارات النطاق |
| Audit | سجل التعديلات والعمليات الحساسة |
| BackupOps | تنسيق النسخ الاحتياطية ومراقبتها؛ الاستعادة ينفذها المطور |
| SystemSettings | إعدادات المطعم والصيانة وحالة استقبال الطلبات |

لا تنشأ وحدات تشغيلية للمخزون أو الموردين أو المشتريات أو المصروفات في هذه المرحلة (DEC-104 وDEC-105). لا تُفعّل المفضلة أو التقييمات أو أي وظيفة مؤجلة إلا وفق آخر ملحق اعتماد نافذ في SRS.

## 4. التكامل بين الوحدات
- OrderPlaced: يصدر بعد نجاح إنشاء الطلب؛ تستقبله Notifications وPrinting وCashier.
- OrderAccepted: يصدر عند قبول الكاشير؛ تبدأ مهمة تذكرة المطبخ الآلية حسب توجيه الطابعة.
- OrderRejected / OrderCancelled: تسجل السبب والمنفذ والتوقيت، وتولد إشعارًا داخليًا.
- PriceChanged / DeliveryFeeChanged: يطلقان إعادة تحقق وموافقة العميل عند وجود سلة مفتوحة.
- EmployeeSuspended: يبطل جلسات الموظف فورًا.
- PrintJobFailed: يسجل الفشل ويبدأ سياسة إعادة المحاولة ويظهر التنبيه.
- BackupFailed / StorageThresholdReached: يولدان تنبيهًا إداريًا.

الأحداث لا تنفذ عمليات مالية أو طباعة مباشرة داخل معاملة HTTP؛ تُرسل المهام عبر Queue مع مفاتيح idempotency لمنع التكرار.

## 5. قواعد العزل وتعدد الفروع
- كل سجل تشغيلي تابع لفرع يحمل branch_id حيث ينطبق.
- مدير الفرع يرى بيانات فرعه فقط؛ المدير الرئيسي يستطيع الاطلاع على جميع الفروع.
- حساب الكاشير مرتبط بفرع محدد مسبقًا.
- إعدادات المنيو والأسعار وساعات العمل والعنوان ووسائل التواصل قابلة للاستقلال لكل فرع.
- يبدأ الإطلاق بفرع الخالدية فقط.

## 6. الطباعة
- تعريف عدة طابعات مع توجيه منفصل لفاتورة العميل وتذكرة المطبخ.
- نسخة مطبخ تلقائية واحدة.
- مهام طباعة ذات حالات ومحاولات وسجل نتيجة مستقل.
- إعادة المحاولة تلقائيًا عند الفشل، مع منع الطباعة المكررة باستخدام معرف مهمة ثابت.
- إدارة واختيار الطابعات من لوحة الإدارة فقط.
- Print Agent وسيط محلي؛ لا يفترض أن خادم الويب يستطيع الوصول مباشرة إلى USB المتصل بجهاز محلي.

## 7. الأمن والامتثال التشغيلي
- RBAC وصلاحيات دقيقة مع تحقق خادمي في كل endpoint/use case.
- إعادة طلب كلمة المرور للعمليات الحساسة.
- سجل تدقيق قبل/بعد وسبب إلزامي لتغيير السعر أو رسوم التوصيل.
- حماية محاولات الدخول والجلسات، وإبطال جلسات الموظف عند الإيقاف.
- لا تخزن بيانات بطاقات أو أسرار دفع ولا يتم التحقق من الدفع الإلكتروني داخل النظام.
- لا تضع مفاتيح أو كلمات مرور أو بيانات إنتاج في Git.

## 8. قرارات تحتاج تفصيلًا في التصميم
- مزود التخزين الخارجي ومزود الطوابير ومزود إرسال البريد/الإشعارات.
- بروتوكول Print Agent والأجهزة المدعومة واختبار USB على أجهزة Android المستهدفة.
- مزود الخرائط وطريقة تحديد موقع الفرع.
- سياسة تقريب وتوزيع الخصومات على مستوى البنود.
- تفاصيل الاحتفاظ القانوني بالسجلات وحذف بيانات العملاء.

هذه نقاط تصميم تفصيلية وليست إذنًا بإضافة مزود أو تكامل دون اعتماد.
