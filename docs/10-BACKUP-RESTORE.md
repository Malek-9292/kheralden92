# النسخ الاحتياطي والاستعادة — فتوش الخالدية

## نطاق Phase 8
- الاستعادة من لوحة الإدارة **غير متاحة** للموظفين (DEC-090)؛ الاستعادة مسؤولية المطوّر/التشغيل فقط.
- يمكن لاحقًا عرض حالة النسخ في الإدارة دون زر استعادة.

## ما يُنسخ
1. قاعدة بيانات MySQL (الجداول التشغيلية كاملة).
2. ملفات `storage/app/public` (صور الأصناف والشعار).
3. `.env` الإنتاجي يُحفظ خارج المستودع في خزنة أسرار، وليس داخل النسخة العامة.

## نسخ احتياطي يدوي موصى به
```bash
# من خادم التطبيق (مثال)
php artisan down
mysqldump --single-transaction --routines --triggers -u"$DB_USERNAME" -p"$DB_PASSWORD" "$DB_DATABASE" | gzip > "fatoosh-$(date +%Y%m%d-%H%M%S).sql.gz"
tar -czf "fatoosh-storage-$(date +%Y%m%d-%H%M%S).tar.gz" -C storage/app public
php artisan up
```

انقل الملفات المشفرة/المضغوطة إلى تخزين خارج الخادم (Object storage أو نسخة غير متصلة). لا تترك النسخ على قرص الإنتاج فقط.

## اختبار الاستعادة (مطور فقط)
1. أنشئ بيئة staging فارغة بنفس إصدار الكود.
2. استعد `.env` من الخزنة (لا تنسخ أسرار الإنتاج إلى أجهزة غير موثوقة).
3. `gunzip -c fatoosh-….sql.gz | mysql …`
4. فك ضغط ملفات التخزين إلى `storage/app/public` ثم `php artisan storage:link`
5. `php artisan migrate --force` فقط إذا كانت النسخة أقدم من الكود؛ وإلا تحقق بالـ health check.
6. سجّل نتيجة الاختبار: التاريخ، حجم النسخة، وقت الاستعادة، نجاح/فشل تسجيل الدخول والطلبات والطباعة.

## جدول مقترح
| التكرار | المحتوى |
|---|---|
| يوميًا | Dump قاعدة البيانات |
| أسبوعيًا | Dump + storage |
| قبل كل نشر | Dump سريع |

## خارج النطاق الحالي
- واجهة استعادة داخل الإدارة.
- نسخ مخزون/موردين/مشتريات (مؤجلة مع الوحدات).
