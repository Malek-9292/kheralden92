# فتوش | Fatoosh Restaurant System

المستودع الرسمي لتوثيق وتطوير نظام إدارة وتشغيل مطعم فتوش الجديد.

## قواعد المشروع
- هذا المشروع مستقل تمامًا عن أي نظام أو مستودع سابق.
- لا يتم تعديل أو نسخ ملفات المشروع القديم إلى هنا دون موافقة صريحة.
- يبدأ العمل بالتوثيق والاعتماد قبل كتابة أي كود.
- المنهج المعماري المستهدف: Modular Monolith.
- كل وثيقة تحمل رقمًا وإصدارًا وحالة اعتماد واضحة.

## الوثائق
- [وثيقة متطلبات النظام SRS](docs/01-SRS.md) — تُضاف بعد اعتماد الملف الأولي.

## التقنية المعتمدة مبدئيًا
- Backend: PHP + Laravel
- Database: MySQL 8
- Frontend: Laravel Livewire + Alpine.js
- Cache & Queue: Redis
- Customer App: PWA

> وجود أي متطلب في الوثائق لا يعني أنه نُفّذ برمجيًا. التنفيذ يبدأ بعد اعتماد التحليل والتصميم.

## حالة التنفيذ الحالية
الفرع `implementation/foundation-v1` مخصص للتنفيذ والمراجعة، ولا يُدمج إلى `main` تلقائيًا. يحتوي حاليًا على أساس المصادقة والصلاحيات والفروع، واجهات Livewire عربية للوحة التحكم والطلبات والأقسام والأصناف ومناطق التوصيل، وواجهات API للكتالوج ومناطق التوصيل وإنشاء الطلب وتتبع الطلب. توجد اختبارات ميزات لهذه الوظائف، ويجب مراجعة نتائج CI على أحدث commit قبل أي نشر. لا تعتبر الطباعة أو PWA أو تشغيل الإنتاج مكتملة حتى يتم تنفيذ اختبارات القبول الفعلية.


## تشغيل بيئة التطوير المحلية

1. يتطلب PHP 8.2 أو أحدث وComposer وقاعدة MySQL 8.
2. انسخ `.env.example` إلى `.env` واضبط بيانات قاعدة بيانات تطوير مستقلة.
3. نفّذ:
   ```bash
   composer install
   php artisan key:generate
   php artisan migrate --seed
   php artisan storage:link
   php artisan fatoosh:admin:create
   php artisan serve
   ```
4. ينشئ الأمر `fatoosh:admin:create` أول مدير نظام تفاعليًا، ويطلب كلمة مرور لا تقل عن 12 حرفًا. لا يوجد حساب مدير افتراضي أو كلمة مرور مضمّنة في المستودع.
5. لا تستخدم بيانات قاعدة الإنتاج في بيئة التطوير.

## واجهات الإدارة الحالية

- `GET /` — واجهة العميل والمنيو والسلة وإرسال الطلب.
- `/manifest.webmanifest` و`/sw.js` — أساس تثبيت PWA على الأجهزة المدعومة.
- `android-print-agent/` — مصدر تطبيق Android Print Agent الأولي لطابعات USB؛ يحتاج بناء APK واختبارًا فعليًا على Epson TM-T20 قبل التشغيل.
- `GET /admin/login` — صفحة تسجيل دخول الموظفين.
- `GET /admin/dashboard` — لوحة مؤشرات التشغيل.
- `GET /admin/orders` — شاشة الطلبات والبحث وتحديث الحالة والتحصيل النقدي حسب الصلاحيات.
- `GET /admin/categories` — إدارة الأقسام.
- `GET /admin/products` — إدارة الأصناف والصور والأسعار والأكثر طلبًا.
- `GET /admin/delivery-areas` — إدارة مناطق التوصيل والرسوم والحد الأدنى.
- `GET /admin/employees` — إدارة حسابات الموظفين والأدوار وفترات الصلاحية.
- `GET /admin/roles` — إنشاء الأدوار وتحديد الصلاحيات.
- `GET /admin/branches` — إدارة الفروع.
- `GET /admin/cashier` — شاشة الكاشير والتحصيل النقدي.
- `GET /admin/printers` — تسجيل الطابعات وإدارة رموز Print Agent ومراجعة المهام الفاشلة.
- `GET /admin/settings` — تخصيص اسم المطعم والشعار والألوان والبانر وبيانات التواصل.
- `GET /admin/search?q=...` — البحث العام داخل وظائف وبيانات الإدارة.

## واجهات الهوية الحالية

- `POST /admin/session` — تسجيل دخول الموظف برقم الهاتف وكلمة المرور.
- `GET /admin/session` — بيانات جلسة الموظف الحالي.
- `DELETE /admin/session` — تسجيل الخروج وإنهاء سجل الجلسة.
- `GET /admin/employees` — قائمة الموظفين (صلاحية `employees.manage`).
- `POST /admin/employees` — إنشاء موظف.
- `PATCH /admin/employees/{employee}` — تعديل الموظف أو إيقافه.
- `GET /admin/roles` — عرض الأدوار والصلاحيات (صلاحية `roles.manage`).
- `POST /admin/roles` و`PATCH /admin/roles/{role}` — إنشاء الأدوار وتعديلها.

كل مسارات الإدارة محمية بالمصادقة وفحص الجلسة الفعالة والصلاحية المناسبة. لا تنشر المشروع على الإنتاج قبل مراجعة CI واختبار واجهات الاستخدام والطباعة على الأجهزة المستهدفة.
